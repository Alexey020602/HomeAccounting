# Модуль Budgets

**Пространство имён:** `HomeAccounting.Budgets`
**Контекст БД:** `BudgetsContext` (схема `budgets`)

## Назначение

Управление бюджетами, их участниками, операциями (ручными тратами) и чеками. Это центральный модуль приложения, через который проходит основная бизнес-логика учёта расходов.

## Основные сущности

### Budget

Корень агрегата. Объединяет участников и все траты.

- `BudgetId` — идентификатор
- `Name` — название
- `BeginOfPeriod` — день месяца, с которого начинается расчётный период
- `Limit` — ограничение по расходам (опционально)
- `CreatorId` — пользователь-создатель
- `CreationDate` — дата создания
- `BudgetUsers` — участники
- `Operations` — операции (ручные траты)

### BudgetUser

Связь пользователя с бюджетом.

- `UserId` — идентификатор пользователя
- `BudgetRoleId` — роль в бюджете

### BudgetRole

Роли участников: **Owner**, **Admin**, **User**. Роль определяет разрешения на чтение, редактирование и удаление бюджета.

### Operation

Трата, добавленная вручную.

- `OperationId`, `Sum`, `Description`, `PurchaseDate`, `AddedDate`
- `UserId` — кто добавил
- `CategoryId` — категория (опционально)

### Receipt

Трата на основе фискального чека.

- `ReceiptId`, `BudgetId`, `UserId`
- Фискальные данные: `Fn`, `Fd`, `Fp`
- `Sum`, `PurchaseDate`, `PurchasePlace`
- `Status` — состояние обработки
- `Products` — товары из чека
- `CompletedAt`, `LastErrorMessage`

### Product

Товар из чека.

- `ProductId`, `Name`, `Quantity`, `Price`, `Sum`
- `CategoryId` — категория (опционально)

### ReceiptProcessingOutboxEntry

Outbox-запись для фоновой обработки чека.

- `Id` — идентификатор записи
- `ReceiptId` — идентификатор чека
- `AttemptCount` — число попыток обработки
- `NextRetryAt` — время следующей повторной попытки
- `LastErrorMessage` — сообщение об ошибке последней попытки (опционально)
- `Status` — состояние обработки

## Пользовательские сценарии

### Работа с бюджетами

1. Пользователь видит список своих бюджетов и выбирает один для работы.
2. Может создать новый бюджет (название, лимит, день начала периода). Создатель автоматически становится Owner.
3. Может просматривать детали бюджета: название, лимит, день начала периода, список участников с ролями.
4. Может редактировать бюджет (при наличии прав Edit).
5. Может удалить бюджет (при наличии прав Delete).
6. Может добавлять/удалять участников бюджета (при наличии прав Edit).

### Учёт трат (операций)

1. Пользователь видит список всех трат выбранного бюджета с фильтрацией и сортировкой.
2. Может добавить трату вручную: сумма, описание, дата покупки, категория (опционально).

### Работа с чеками

1. Пользователь добавляет чек одним из способов: ввод фискальных данных вручную, загрузка файла с QR-кодом, сканирование QR-кода.
2. Если чека с такими фискальными данными (ФД, ФН, ФП) ещё не было, он добавляется со статусом «Обрабатывается».
3. В фоне запускается обработка чека через ФНС (подробнее в [Receipt Processing](receipt-processing.md)).
4. Пользователь видит список чеков с их статусами и может просматривать детали.
5. Для обработанных чеков можно назначать/снимать категории с отдельных товаров.

### Главная страница

Отображает приветствие с названием выбранного бюджета, меню основных функций и краткую статистику. Если бюджет не выбран — перенаправление на экран выбора.

## API endpoints

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/budgets` | Список бюджетов текущего пользователя |
| `POST` | `/api/budgets` | Создать бюджет |
| `GET` | `/api/budgets/{id}` | Детали бюджета |
| `PUT` | `/api/budgets/{id}` | Обновить бюджет |
| `DELETE` | `/api/budgets/{id}` | Удалить бюджет |
| `GET` | `/api/budgets/{id}/users` | Список участников бюджета |
| `POST` | `/api/budgets/{id}/users` | Добавить участника |
| `DELETE` | `/api/budgets/{id}/users/{userId}` | Удалить участника |
| `GET` | `/api/budgets/{id}/permissions` | Права текущего пользователя |
| `GET` | `/api/budgets/{id}/spendings` | Все траты (операции + чеки) |
| `GET` | `/api/budgets/{id}/operations` | Операции (фильтр, сортировка, пагинация) |
| `GET` | `/api/budgets/{id}/receipts` | Чеки (фильтр, сортировка, пагинация) |
| `POST` | `/api/budgets/{id}/spendings/manual` | Добавить ручную трату |
| `POST` | `/api/budgets/{id}/receipts` | Добавить чек (фискальные данные) |
| `POST` | `/api/budgets/{id}/receipts/file` | Добавить чек из файла с QR |
| `POST` | `/api/budgets/{id}/receipts/qrcode` | Добавить чек из строки QR |
| `PUT` | `/api/budgets/{budgetId}/receipts/{receiptId}/products/{productId}/category` | Назначить категорию товару |
| `DELETE` | `/api/budgets/{budgetId}/receipts/{receiptId}/products/{productId}/category` | Снять категорию с товара |
| `GET` | `/api/products` | Список уникальных названий товаров (из чеков), пагинация, фильтр и сортировка по имени |
| `GET` | `/api/products/csv` | Экспорт уникальных названий товаров в CSV |

Эндпоинты `/api/products` и `/api/products/csv` реализованы в модуле Budgets (данные из агрегата чека).

## Ограничения и правила

- Все изменения в контексте Budgets идут через агрегат Budget или через сценарии, загружающие бюджет.
- Авторизация по ресурсу: `BudgetRequirements(BudgetPermissions.Read/Edit/Delete)` через `IAuthorizationService`.
- Обработка чеков (ФНС, retry) выполняется асинхронно в фоне, обновление Receipt — отдельные транзакции.
- Уникальность чека определяется комбинацией фискальных данных (ФД, ФН, ФП).

## Зависимости от других модулей

- **ReceiptProcessing** — через `IReceiptProcessService` для получения данных чека из ФНС.
- **Categories** — через `CategoryId` для привязки категорий к операциям и товарам.
- **Users** — через `UserId` для привязки участников и авторства трат.
