# Модуль Users

**Пространство имён:** `HomeAccounting.Users`
**Контекст БД:** `UsersContext` (схема `Identity`)

## Назначение

Регистрация, аутентификация, управление профилем пользователя и жизненным циклом токенов. Модуль отвечает за всё, что связано с идентичностью пользователя в системе.

## Основные сущности

### User

Корень агрегата. Свойства:

- Логин (уникальный)
- Полное имя
- Пароль (хеш)

### RefreshToken

Токен обновления, привязанный к пользователю и сессии.

- `Token` — хеш (SHA256) от случайного значения
- `ExpiresAt` — срок действия
- `UsedAt` — когда был использован (для ротации)
- `RevokedAt` — когда был отозван
- `JwtId` — связь с JWT access token
- `UserId` — владелец
- `SessionId` — идентификатор сессии

## Пользовательские сценарии

### Регистрация

1. Пользователь заполняет форму: логин (с проверкой доступности), полное имя, пароль, подтверждение пароля.
2. После регистрации автоматически выполняется вход.
3. Пользователь перенаправляется на экран выбора бюджета.

### Вход в систему

1. Пользователь вводит логин и пароль.
2. Сервер возвращает JWT access token и refresh token.
3. Токены сохраняются в `localStorage` браузера.
4. Пользователь перенаправляется на главную страницу или экран выбора бюджета.

### Управление профилем

1. Пользователь получает свои данные по идентификатору или логину: `GET /api/users/{id}` или `GET /api/users/{username}`.
2. Может редактировать логин и полное имя: `PUT /api/users/{id}` (id текущего пользователя).

### Обновление токена

1. При истечении JWT access token клиент автоматически вызывает refresh.
2. Сервер проверяет refresh token, выполняет ротацию (старый помечается как использованный, выдаётся новый).
3. При неудачном обновлении — перенаправление на экран входа.

Подробнее о механике токенов см. [Аутентификация](../architecture/auth.md).

### Выход

- **Logout** — отзыв текущей сессии (refresh token).
- **Logout All** — отзыв всех сессий пользователя.

## API endpoints

| Метод | Путь | Описание | Авторизация |
|---|---|---|---|
| `POST` | `/api/register` | Регистрация | Анонимный |
| `POST` | `/api/login` | Вход | Анонимный |
| `GET` | `/api/login/exist` | Проверка существования логина | Анонимный |
| `POST` | `/api/refresh` | Обновление токена | Анонимный |
| `POST` | `/api/logout` | Выход (текущая сессия) | Анонимный |
| `POST` | `/api/logout/all` | Выход (все сессии) | Анонимный |
| `GET` | `/api/users/{id}` | Получить пользователя по идентификатору (guid) | Требуется |
| `GET` | `/api/users/{username}` | Получить пользователя по логину | Требуется |
| `PUT` | `/api/users/{id}` | Обновить профиль (логин, полное имя) по идентификатору | Требуется |

## Фоновые процессы

### TokensCleanupWorker

Фоновый сервис (`BackgroundService`), который периодически удаляет истёкшие refresh-токены.

- Интервал: каждые 7 дней (настраивается через `TokensCleanup:DayInterval`)
- Удаляет токены, истёкшие более 30 дней назад
- Пакетная обработка: 50 000 записей за раз с паузой 200 мс между пакетами

## Зависимости от других модулей

- Модуль Users не зависит от других доменных модулей.
- Другие модули (Budgets) ссылаются на `UserId` для идентификации пользователей.
