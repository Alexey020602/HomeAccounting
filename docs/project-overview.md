# HomeAccounting — обзор проекта

## Цель

HomeAccounting — приложение для учёта и анализа личного бюджета. Пользователь фиксирует траты на основе данных чека или введённых вручную данных в рамках одного из бюджетов, в которых он принимает участие.

Проект также является обучающим: он используется для освоения современных подходов разработки на C# и развивается с оглядкой на [evolutionary-architecture-by-example](https://github.com/evolutionary-architecture/evolutionary-architecture-by-example).

## Модель данных

### Бюджет (Budget)

Корневая сущность. Свойства:

- Название
- День месяца, с которого начинается расчётный период (например, день выплаты зарплаты)
- Ограничение по расходам (Limit)
- Пользователь-создатель
- Дата создания
- Участники бюджета (BudgetUser) с ролями (Owner, Admin, User)
- Операции (траты) в рамках бюджета

### Операция / трата (Operation)

- Сумма
- Описание
- Дата покупки
- Дата добавления
- Категория (опционально)
- Пользователь, добавивший трату

### Чек (Receipt)

Трата на основе фискальных данных чека. Дополнительные свойства:

- Фискальные данные (ФД, ФН, ФП, сумма, дата покупки)
- Место покупки
- Список товаров (если успешно обработано)
- Состояние обработки: Обрабатывается → Обработано / Ошибка
- Текст ошибки (если есть)

### Товар (Product)

- Название
- Стоимость
- Количество
- Сумма
- Категория (опционально)

### Категория (Category)

- Название
- Родительская категория (дерево через `ParentCategoryId`)
- Иерархия (path-based через `CategoryHierarchy`)

## Bounded contexts

Бэкенд организован по bounded context'ам (неймспейсы-модули) и вертикальным срезам (один use case — одна папка).

| Контекст | Ответственность | Пространство имён |
|---|---|---|
| **Budgets** | Бюджеты, участники, операции, чеки, фоновая обработка чеков, справочник уникальных названий товаров (эндпоинты `/api/products`, `/api/products/csv`) | `HomeAccounting.Budgets` |
| **Users** | Регистрация, аутентификация, профиль, refresh-токены | `HomeAccounting.Users` |
| **Categories** | Справочник категорий (дерево) | `HomeAccounting.Categories` |
| **ReceiptProcessing** | Получение данных чека из ФНС: контракт и интеграция | `HomeAccounting.ReceiptProcessing` |

## Агрегаты и транзакционные границы

- **Budgets**: корень агрегата — `Budget`. Участники (`BudgetUser`), операции (`Operation`), чеки (`Receipt`) и товары (`Product`) изменяются в одну транзакцию с бюджетом. Обработка чека (ФНС, retry) выполняется асинхронно в фоне, обновление `Receipt` — отдельные транзакции.
- **Users**: корень — `User`. Refresh-токены (`RefreshToken`) привязаны к пользователю.
- **Categories**: корень — `Category` (дерево через родительскую ссылку).

## Правила для кода

- Код сгруппирован по вертикальным срезам: один use case — одна папка (эндпоинт + запрос/ответ + обработчик).
- Модули не ссылаются друг на друга напрямую по доменной логике. Общее — в `Common`, пересечение контекстов — через интерфейсы (например, `Budgets` использует `ReceiptProcessing` через `IReceiptProcessService`).
- На этапе MVP допускается ссылаться на типы идентификаторов из других контекстов (`UserId`, `CategoryId`) для связей между агрегатами.
